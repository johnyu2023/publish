## 迅投投研版里的 python 策略，和 py 文件的区别

+ 迅投（ThinkTrader）投研版里的 Python 策略**本质上就是一个 `.py` 文件**，你完全可以用 VS Code 或 PyCharm 编写它。

+ 它与“普通 Python 代码”的区别，就像是**“插件”与“独立程序”**的区别。普通的 Python 程序是从 `main()` 函数开始自主运行的，而迅投策略是运行在**迅投引擎托管环境**下的脚本。

### 核心区别的详细对比

#### 1. 运行机制：被动调用 vs 主动执行

+ **普通 Python：** 你写好代码，运行 `python main.py`，程序从第一行执行到最后一行。
+ **迅投策略：** 你编写的是一组**回调函数（Event Selection）**。迅投的行情引擎像一个“节拍器”，每当行情跳动一次（Tick）或一根 K 线走完（Bar），它就会自动去调用你代码里的某个特定函数。

#### 2. 核心结构的区别
一个标准的迅投策略必须包含几个特定的“钩子”函数，而普通代码没有这种强制要求：

| 功能模块 | 迅投策略中的函数 | 作用 |
| :--- | :--- | :--- |
| **初始化** | `init(Context)` | 策略启动时执行一次，用于设置初始资金、基准、选股范围。 |
| **行情驱动** | `handle_bar(Context, Bar)` | **核心。** 每产生一根新 K 线，引擎就调用一次此函数，你在这里写买卖逻辑。 |
| **盘前处理** | `before_trading(Context)` | 每天开盘前执行，适合做选股过滤。 |

#### 3. 对象与库的内置（Context 对象）
这是最大的技术区别。在迅投中，有一个贯穿始终的对象叫 **`Context`**。

+ **普通代码：** 如果你想知道账户还有多少钱，你需要调用银行或券商的 API 接口。
+ **迅投策略：** 账户资金、持仓、当前时间、股票代码等全部封装在 `Context` 对象里。
  + 例如：`Context.cash` 获取现金，`Context.account_id` 获取账号。

#### 4. 数据获取方式

+ **普通代码：** 你需要自己找数据源（如 tushare, yfinance），写爬虫或调用接口，然后存入 DataFrame。
+ **迅投策略：** 迅投内置了高效的数据接口（如 `get_market_data` 或 `get_history_data`）。你不需要关心数据从哪来，直接调用函数，行情数据就会以极快的速度填充进你的变量中。

---

#### 5. 代码示例对比

##### 普通 Python (假设你要买股票)

```python
import some_broker_api

def main():
    api = some_broker_api.login("user", "password")
    price = api.get_last_price("600519.SH")
    if price < 1500:
        api.buy("600519.SH", 100)

main()
```

##### 迅投 Python 策略

```python
def init(Context):
    Context.stock = "600519.SH"

def handle_bar(Context, bar):
    # 引擎自动传入当前 bar 的数据
    current_price = bar.close 
    if current_price < 1500 and Context.portfolio.cash > 200000:
        # 使用内置下单函数
        order_shares(Context.stock, 100)
        print(f"{Context.now} 已触发买入")
```

### 总结
**区别在于“语境”：**

1. **普通 Python** 是你在指挥计算机做事。
2. **迅投 Python** 是你在告诉迅投：“**如果**行情变成这样，**你就**帮我做那件事”。

你依然可以使用 `pandas`、`numpy` 甚至 `scikit-learn` 来做计算，这些在迅投环境里都是通用的。

## 迅投投研版 和 QMT 是什么关系，为什么说 Mini QMT 是由券商提供的

+ **迅投投研版**和 **QMT**（Quantitative Method Trading）是同一家公司的不同产品定位，而 **Mini QMT** 则是为了解决券商风控和合规需求而产生的“精简版”客户端。

### 1. 核心关系：产品线与终端形态
它们都出自**迅投（xuntou）**公司。你可以把它们理解为“标准版”与“量化特供版”的关系：

+ **迅投投研版：** 主要是面向普通投资者或机构研究员的综合性终端。它更像是一个功能极其强大的同花顺或东方财富，除了基础看盘，还集成了深度投研资料、多仓管理、算法交易等功能。
+ **QMT（全量版）：** 这是专门为量化交易开发者设计的终端。它内置了 Python 运行环境和策略编辑器，逻辑是“**行情 + 策略运行 + 交易**”一体化，策略直接在 QMT 进程内运行。

---

### 2. 为什么说 Mini QMT 是由券商提供的？
这涉及到量化交易的**合规性**与**部署方式**。通常情况下，量化软件需要接入券商的交易系统（柜台），而券商为了控制风险和方便用户，采取了以下合作模式：

#### 为什么会有 "Mini" 模式？
早期的 QMT 需要用户把 Python 策略写在软件内部，这导致了一些痛点：

1. **环境限制：** 用户无法灵活使用自己本地的 IDE（如 VS Code）或特定版本的 Python 库。
2. **风控合规：** 券商需要确保每一笔自动化交易都通过其合规审查。

#### 券商提供的本质

+ **极简封装：** 所谓的 Mini QMT，本质上是券商提供的一个**后台交易进程**。它去掉了前端繁琐的 UI 界面和内置的 Python 编辑器。
+ **API 授权：** 券商通过 Mini QMT 开放了 `xtquant` 库。这允许你直接在**本地环境**（比如你常用的 Python 环境）中通过代码调用券商的交易柜台。
+ **身份凭证：** 只有当你拥有券商开立的量化权限账号时，你才能登录并使用 Mini QMT 进行实盘下单。

---

### 3. 三者的对比直观理解

| 特性 | 迅投投研版 | QMT (全量版) | Mini QMT (极简版) |
| :--- | :--- | :--- | :--- |
| **主要用途** | 深度投研、手动/算法交易 | 自动化策略研发与执行 | 本地环境 API 调用交易 |
| **运行环境** | 客户端 UI | 客户端内置 Python | **本地 Python 环境** |
| **编写代码** | 较少（支持简单脚本） | 在软件内置编辑器编写 | 在 VS Code / PyCharm 编写 |
| **券商角色** | 软件授权方 | 提供专用量化席位 | **提供接口网关与实盘通道** |
