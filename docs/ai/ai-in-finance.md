## 开源项目 TradingAgents

+ 基于 **大语言模型（LLM）的多智能体协作金融交易框架**（通常关联论文 *"TradingAgents: Multi-AI Agents Collaborative Financial Trading Framework"*）。

+ 这个项目旨在模拟现实世界中的专业交易团队，通过多个 AI 智能体（Agent）扮演不同角色（如分析师、交易员、风控官等），共同协作完成金融交易决策。

---

### 1. 项目核心理念
传统的量化交易通常依赖单一的数学模型或强化学习算法。而 `TradingAgents` 的核心理念是 **“协作与辩论”**。它认为交易决策应该像人类交易团队一样，经过多方分析、讨论和风险评估后得出，而不是由单一模型直接输出。

+ **多智能体架构 (Multi-Agent System):** 系统由多个独立的 LLM Agent 组成。
+ **角色扮演 (Role-Playing):** 每个 Agent 被赋予特定的专业角色和提示词（Prompt）。
+ **协作机制 (Collaboration):** Agent 之间可以共享信息、互相质疑、投票或加权决策。

### 2. 典型的智能体角色架构
虽然不同版本的实现略有差异，但一个标准的 `TradingAgents` 框架通常包含以下角色：

1. **基本面分析师 (Fundamental Analyst Agent):**
    + 负责分析公司财报、宏观经济数据、行业新闻。
    + 判断资产的长期价值。
2. **技术面分析师 (Technical Analyst Agent):**
    + 负责分析 K 线图、技术指标（MACD, RSI, 均线等）。
    + 寻找入场和离场的时机。
3. **情绪分析师 (Sentiment Analyst Agent):**
    + 负责抓取社交媒体（Twitter, Reddit）、新闻头条。
    + 分析市场情绪（恐慌或贪婪）。
4. **交易员 (Trader Agent):**
    + 综合上述分析师的建议。
    + 生成具体的交易指令（买入/卖出/持有，仓位大小）。
5. **风控经理 (Risk Manager Agent):**
    + 拥有“一票否决权”。
    + 评估当前仓位风险、回撤限制，确保交易符合风控规则。

### 3. 工作流程 (Workflow)

1. **数据收集:** 系统自动获取市场数据、新闻、财报等。
2. **独立分析:** 各分析类 Agent 并行处理数据，生成初步观点。
3. **会议/辩论 (Meeting/Debate):** Agent 们在一个共享上下文中交流。例如，技术面看涨，但基本面看跌，它们需要论证各自的观点。
4. **决策生成:** 交易员 Agent 根据辩论结果制定策略。
5. **风控审核:** 风控 Agent 审核策略，若风险过高则拦截或调整仓位。
6. **执行与回测:** 通过 API 执行交易或在历史数据上进行回测。

### 4. 技术栈 (Tech Stack)

+ **编程语言:** Python (主流)。
+ **LLM 框架:** LangChain, AutoGen, LlamaIndex 等（用于构建 Agent 交互）。
+ **大模型:** 支持接入 GPT-4, Claude, 或本地部署的 Llama 3 等开源模型。
+ **数据源:** Yahoo Finance, Alpha Vantage, 加密货币交易所 API 等。
+ **回测引擎:** Backtrader, Zipline 或自定义回测模块。

### 5. 项目的优势与价值

+ **可解释性强:** 相比黑盒的深度学习模型，Agent 的“辩论过程”留下了文本日志，人类可以理解为什么要进行这笔交易。
+ **灵活性:** 可以通过修改 Prompt 快速调整 Agent 的策略风格（如从激进转为保守）。
+ **信息融合:** 能够同时处理非结构化数据（新闻文本）和结构化数据（价格序列）。
+ **开源学习:** 为开发者提供了一个学习如何构建多 Agent 系统的绝佳案例。

### 6. 局限性与风险 (非常重要)
尽管项目很酷，但必须清醒认识到其局限性：

+ **幻觉问题 (Hallucination):** LLM 可能会编造数据或错误解读新闻，导致错误交易。
+ **延迟与成本:** 多轮 Agent 对话需要调用多次 LLM API，速度慢且 Token 成本高，不适合高频交易。
+ **市场适应性:** 历史表现不代表未来，LLM 训练数据有截止时间，可能无法理解突发的“黑天鹅”事件。
+ **非投资建议:** **GitHub 上的此类项目主要用于学术研究和教育，严禁直接用于真实资金交易，除非你经过极其严格的测试。**

## AI在金融行业的使用原则

+ 营销和风控是在金融行业中两个非常重要的场景。
+ 营销就是给客户推荐我们的产品，我们希望做到千人千面，进行个性化的推荐。
+ 大模型靠"参数规模"泛化，小模型靠"特征工程+业务理解"取胜。金融场景更依赖后者。

## 客户分层营销助手

### 工作原理

+ AI助手通过分析客户资产规模、交易频率和风险偏好，**自动生成分层标签**（如高净值活跃型、稳健保守型等），
**并智能匹配个性化营销策略**。系统会推荐最佳接触时机（如市场波动时）、优选渠道（短信/电话/APP推送）及
定制话术（如高收益推荐或稳健配置建议）

+ Coze 里有数据库，也有知识库。谁会被先执行？ Coze 会先运行知识库，然后再执行数据库查询
+ 这个例子是可以创建工作流的，将它转变为调用工作流
+ 知识库 - 相似度检索。里面是存放文件，是一个召回的概念。文件里内容比较多，是通过相似度匹配来召回的，选择 top 5 个 chunks
+ 数据库 - 确定性的检索。

### 适应场景

> 核心逻辑均为“数据分层—策略匹配—精准触达”，适配需强客户分群的行业。

+ 银行理财：根据客户存款、投资偏好分层，匹配存款升级、基金定投等产品，通过客户经理或手机银行推送。
+ 保险销售：按家庭资产、健康风险分级，推荐重疾险、年金险等，定制电销话术或线下拜访策略。
+ 电商零售：基于消费金额、频次划分VIP/普通客户，推送大促优惠或会员专享活动，提升复购率。
+ 汽车销售：依据收入、车型偏好分层，针对高潜客户提供试驾邀约或金融分期方案。
+ 奢侈品行业：识别高消费力客户，私域推送限量款或专属活动，强化高端服务体验。

### 智能客服（多Agent）适用场景

> 高频咨询+复杂投诉分离，适配高并发、多任务的服务场景。

+ 银行服务：营销Agent推荐理财/信用卡，投诉Agent处理账户异常或交易纠纷，双线程提升效率。
+ 电商平台：导购Agent解答商品/促销问题，售后Agent处理退换货或物流投诉，优化用户体验。
+ 电信运营商：业务Agent办理套餐升级，故障Agent解决网络/话费争议，缩短服务链路。
+ 政务热线：咨询Agent解读政策法规，投诉Agent跟进行政效率问题，强化公共服务效能。
+ 医疗健康：导诊Agent提供科室/挂号指导，投诉Agent处理医患沟通或费用纠纷。
+ 航空出行：售票Agent查询航班/改签，投诉Agent补偿延误或行李丢失，分层服务旅客需求。
